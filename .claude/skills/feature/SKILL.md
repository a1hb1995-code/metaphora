# /feature 워크플로

## 1. 이해 & 계획
- 요청을 한 문장으로 재진술하고, 관련 파일(라우트/서비스/클라이언트/타입/페이지)을 읽는다.
- 수용 기준(acceptance criteria)을 3~5개 체크리스트로 적는다. 각 항목은 **검증 가능한 문장**이어야 한다
  (예: "POST /api/x 에 음수 amount를 보내면 400").
- 결과를 바꾸는 모호한 결정만 사용자에게 묻는다. 나머지는 기본값을 택하고 명시한다.

## 2. 구현 (작은 단계)
- 백엔드 → 클라이언트/타입 → 화면 순서로 진행.
- 각 단계 후 `harness/check.sh --scope <패키지> --fast`로 빠르게 확인한다.
- API를 추가/변경하면 `/api-endpoint` 체크리스트를 따른다.
- 서비스 로직을 바꿨다면 `test-writer` 서브에이전트로 테스트를 추가한다.

## 3. 검증
- `harness/check.sh` 전체 PASS.
- API 변경 시 `harness/smoke.sh`에 케이스를 추가하고 PASS 확인.
- 수용 기준을 하나씩 실제 명령 결과로 체크한다. 확인하지 못한 항목은 "미확인"으로 남긴다.

## 4. 리뷰
- `reviewer` 서브에이전트를 호출한다. BLOCKER는 모두 고치고 3단계로 돌아간다.

## 5. 기록 & 보고
- `harness/progress.md`에 `- YYYY-MM-DD 기능명: 한 일 / 남은 일` 한 줄 추가.
- 사용자에게: 수용 기준 체크 결과, 게이트/스모크 결과, 남은 리스크를 짧게 보고.
